# 智游北京——验收标准

> 本文使用 Given/When/Then 描述可验证场景。除非特别说明，所有场景均应同时满足权限控制、输入校验和中文反馈要求。

## 1. 通用验收约定

- 使用包含约 20～30 个北京景点的固定测试数据集。
- 使用游客、普通用户、管理员三类测试身份。
- 涉及“今天”的规则以服务端 Asia/Shanghai 日期为准。
- Must 场景全部通过，才满足 MVP 完成定义。
- 性能测试应在团队记录的统一测试环境和数据规模下执行。
- 用户通过手工界面步骤可以完成核心流程；关键规则同时具有自动化测试。

## 2. 游客与账号

### AC-US-001 浏览景点列表

1. **正常展示**
   - Given 系统中存在已上架景点
   - When 游客进入景点列表页
   - Then 系统展示景点摘要，且每项至少包含名称、分类、图片和参考票价
2. **没有可用数据**
   - Given 系统中不存在已上架景点
   - When 游客进入景点列表页
   - Then 系统展示明确空状态，不显示服务异常页面

### AC-US-002 搜索与筛选景点

1. **关键词搜索**
   - Given 已上架景点中存在名称或简介包含“故宫”的记录
   - When 游客搜索“故宫”
   - Then 结果仅包含名称或简介匹配的已上架景点
2. **组合筛选**
   - Given 系统存在不同分类、价格和标签的景点
   - When 游客同时选择“历史文化”、指定价格区间和兴趣标签
   - Then 每条结果同时满足所有已选条件
3. **无匹配结果**
   - Given 没有景点满足当前条件
   - When 游客提交搜索或筛选
   - Then 系统显示“未找到符合条件的景点”及清除条件入口

### AC-US-003 查看景点详情

1. Given 某景点已上架
2. When 游客打开该景点详情
3. Then 页面展示名称、分类、简介、图片、地址、开放时间、建议游玩时长、参考票价、标签、评分和热度
4. And 页面只展示当前可见评价
5. And 页面展示地址与经纬度，并提供包含该景点位置的第三方地图导航链接
6. And 第三方地图不可用时，本页面其他内容和站内核心操作仍可使用

### AC-US-004 注册账号

1. **注册成功**
   - Given 用户名去除首尾空格后仅包含中文、英文字母、数字或下划线且长度为 3～20 个字符，密码长度为 8～64 个字符，且规范化用户名未被使用
   - When 游客提交注册
   - Then 系统创建普通用户账号，且密码不以明文保存
2. **重复用户名**
   - Given 用户名已存在
   - When 游客使用仅英文字母大小写或首尾空格不同的等价用户名注册
   - Then 系统拒绝创建账号，并指出用户名已被使用
3. **无效输入**
   - Given 规范化后的用户名少于 3 个、多于 20 个或包含规则外字符，或密码少于 8 个或多于 64 个字符
   - When 游客提交注册
   - Then 系统不创建账号，并在对应字段附近显示错误原因
4. **不要求联系方式**
   - Given 用户提供合法用户名和密码，但未提供邮箱或手机号
   - When 游客提交注册
   - Then 系统仍可成功创建普通用户账号

### AC-US-005 登录与退出

1. **登录成功**
   - Given 普通用户或管理员提供正确凭据
   - When 提交登录
   - Then 系统建立对应身份的有效会话并进入允许访问的页面
2. **登录失败**
   - Given 凭据错误
   - When 提交登录
   - Then 系统拒绝登录，且不泄露具体是用户名还是密码错误
3. **退出**
   - Given 用户已经登录
   - When 用户执行退出
   - Then 当前会话失效，再次访问受保护页面时需重新登录

### AC-US-006 角色访问控制

1. Given 普通用户已登录
2. When 该用户通过页面地址或直接接口请求管理员资源
3. Then 系统拒绝请求并返回合适的未授权/禁止访问结果
4. Given 用户 A 已登录
5. When 用户 A 请求读取或修改用户 B 的收藏、方案、预约或评价
6. Then 系统拒绝请求，且用户 B 的数据保持不变

## 3. 收藏与景点发现

### AC-US-007 管理收藏

1. Given 用户已登录且尚未收藏景点 A
2. When 用户收藏景点 A
3. Then 景点 A 出现在该用户收藏列表中
4. When 用户再次尝试收藏景点 A
5. Then 系统不创建重复收藏记录，并给出幂等或明确反馈
6. When 用户取消收藏景点 A
7. Then 景点 A 不再出现在该用户收藏列表中

### AC-US-008 排序景点（Should）

1. Given 搜索结果包含不同热度、评分和价格的景点
2. When 游客选择某个支持的排序方式
3. Then 所有当前结果按所选指标和方向稳定排列

### AC-US-009 查看嵌入式地图位置（Should）

1. Given 景点具有有效经纬度
2. When 游客查看景点详情
3. Then 页面在地图上标明景点位置

## 4. 智能行程规划

### AC-US-010 提交行程偏好

1. **合法条件**
   - Given 用户已登录
   - When 用户提交未来或当天的开始日期、1～7 天、统一适用于所有游玩日的有效每日时间段、非负预算及至少一个兴趣标签
   - Then 系统接受条件并开始生成行程
2. **非法条件**
   - Given 天数非正数或超过上限、结束时间不晚于开始时间、预算为负数或缺少必填项
   - When 用户提交条件
   - Then 系统拒绝生成并逐项说明错误

### AC-US-011 生成可解释行程

1. **完整方案**
   - Given 存在足够多满足兴趣、预算、开放时间和时间容量的候选景点
   - When 用户生成行程
   - Then 系统在 5 秒内返回按天分组的方案
   - And 每个景点包含预计时段、游玩时长、费用和至少一条推荐理由
   - And 相邻景点的交通时间按经纬度直线距离、20 km/h 估算速度和 15 分钟换乘时间计算，并向上取整到 5 分钟
   - And 页面将估算交通时间标注为非实时参考值
   - And 同一方案不重复安排景点
   - And 每日安排不超过用户设置的可用时间
   - And 总参考票价不超过用户预算
2. **候选不足**
   - Given 只有部分景点满足约束
   - When 用户生成行程
   - Then 系统返回可行的部分方案并说明未排满的主要原因
3. **无可用方案**
   - Given 没有任何景点满足核心约束
   - When 用户生成行程
   - Then 系统不保存空方案，并提示用户放宽预算、时间或兴趣条件
4. **可解释排序**
   - Given 两个候选景点仅兴趣匹配度存在明显差异
   - When 其他评分因素相同或被测试夹具固定
   - Then 兴趣匹配度更高的景点具有更高推荐分数

### AC-US-012 保存行程

1. Given 用户已生成非空方案并填写合法名称
2. When 用户选择保存
3. Then 系统创建归属于当前用户的方案并提示保存成功
4. And 用户重新登录后仍能查看该方案及其中的分日顺序

### AC-US-013 调整行程景点顺序

1. Given 已保存方案某一天包含至少两个景点
2. When 用户对非首项执行上移
3. Then 该景点与前一景点交换顺序并被持久保存
4. When 用户对非末项执行下移
5. Then 该景点与后一景点交换顺序并被持久保存
6. When 用户删除某景点并确认
7. Then 该景点从方案中移除，其他景点保持相对顺序
8. And 首项不可继续上移、末项不可继续下移
9. And 上移、下移仅能发生在同一天内，不提供跨天移动
10. And 每次调整后系统重新计算当天预计时段、交通时间和方案总费用
11. Given 调整后的预计时段超出景点开放时间或用户的每日可用时间段
12. Then 系统保留调整结果，并在相关行程日和景点上显示冲突警告

### AC-US-014 管理已有行程（Should）

1. Given 用户拥有已保存方案
2. When 用户提交合法的新名称
3. Then 方案名称被更新
4. When 用户确认删除整份方案
5. Then 方案及其行程项不再出现在该用户列表中
6. And 其他用户不能重命名或删除该方案

### AC-US-015 复制行程（Could）

1. Given 用户拥有已保存方案
2. When 用户选择复制
3. Then 系统创建内容相同但 ID 不同的新方案
4. And 修改复制方案不会改变原方案

## 5. 模拟预约

### AC-US-016 创建预约

1. **预约成功**
   - Given 用户已登录并选择可预约景点、当天至未来 90 天内的日期、该景点支持的场次和 1～10 人
   - When 用户确认预约
   - Then 系统生成唯一预约编号，状态为“待游览”，并保存当时的景点必要快照
2. **预约失败**
   - Given 日期已过去或超过未来 90 天、场次不属于上午/下午/全天或景点不支持该场次、人数小于 1 或大于 10，或存在缺失字段
   - When 用户确认预约
   - Then 系统拒绝创建，指出错误字段，且数据库中没有半完成预约
3. **重复预约**
   - Given 用户已存在同一景点、同一日期和同一场次的未取消预约
   - When 用户再次提交相同组合的预约
   - Then 系统拒绝创建重复预约并说明原因
   - When 原预约被取消后，用户再次提交相同组合
   - Then 系统允许在其他字段合法时创建新预约

### AC-US-017 查看预约

1. Given 用户拥有不同状态的预约
2. When 用户进入“我的预约”
3. Then 系统只展示当前用户的预约
4. And 每条记录包含预约编号、景点、日期、场次、人数和状态

### AC-US-018 取消预约

1. **允许取消**
   - Given 预约状态为“待游览”且游览日期未到
   - When 用户确认取消
   - Then 状态更新为“已取消”，且再次取消不会产生额外状态变化
2. **拒绝取消**
   - Given 预约已取消或游览日期已过
   - When 用户尝试取消
   - Then 系统拒绝操作并说明原因

## 6. 评价

### AC-US-019 查看评价

1. Given 景点同时存在可见和已隐藏评价
2. When 任意访问者查看景点详情
3. Then 页面只展示可见评价
4. And 平均评分只由当前有效且可见的评价计算

### AC-US-020 提交评价

1. **评价成功**
   - Given 用户拥有该景点游览日期已过且未取消、未评价的预约
   - When 用户提交 1～5 整数评分和符合长度限制的正文
   - Then 系统创建评价并更新公开平均评分
2. **无资格评价**
   - Given 用户没有合格预约，或预约已取消、日期未到或已被评价
   - When 用户尝试提交评价
   - Then 系统拒绝提交并说明原因
3. **无效内容**
   - Given 评分越界、不是整数，或正文少于 5 个或多于 500 个字符
   - When 用户提交评价
   - Then 系统拒绝提交并标识无效字段

### AC-US-021 删除自己的评价

1. Given 用户已发表评价
2. When 评价作者确认删除
3. Then 评价被逻辑删除，不再公开展示，且景点平均评分被重新计算
4. And 管理员不能恢复这条由作者主动删除的评价
5. Given 另一普通用户已登录
6. When 该用户尝试删除这条评价
7. Then 系统拒绝操作且评价保持不变

## 7. 管理后台

### AC-US-022 管理景点

1. **新增**
   - Given 管理员已登录并填写全部合法必填字段
   - When 管理员保存新景点
   - Then 景点被创建并可按其上架状态出现在前台
2. **字段校验**
   - Given 票价为负数、开放时间无效、经纬度非法或缺少必填项
   - When 管理员保存
   - Then 系统拒绝保存并指出错误字段
   - And 分类和兴趣标签只能从需求规定的固定词表中选择
3. **修改**
   - Given 景点已经存在
   - When 管理员修改并保存合法信息
   - Then 后续详情和新推荐使用更新后的信息
   - And 每个星期日只能配置为关闭或配置一个开放时间段，不支持同日多段时间
4. **下架**
   - Given 景点存在于历史行程或预约中
   - When 管理员下架该景点
   - Then 景点不再进入新的列表、搜索、推荐和预约入口
   - And 历史行程和预约仍显示可理解的景点快照
   - And 已有待游览预约仍可由预约用户取消，未取消预约完成后仍可用于评价资格判断

### AC-US-023 查看预约记录

1. Given 系统存在多个用户、日期、景点和状态的预约
2. When 管理员进入预约管理页
3. Then 管理员可查看预约摘要
4. When 管理员按日期、景点或状态筛选
5. Then 结果仅包含满足全部已选条件的记录
6. And 管理页面及管理员接口不提供替用户修改或取消预约的能力

### AC-US-024 管理评价可见性

1. Given 某评价当前可见
2. When 管理员隐藏该评价
3. Then 公开页面不再展示该评价，且平均评分被重新计算
4. When 管理员恢复该评价
5. Then 评价重新公开展示，且平均评分再次更新
6. And 隐藏和恢复不会改变评价作者、评分或正文

### AC-US-025 查看运营概览（Should）

1. Given 系统存在用户、景点、预约、行程和收藏/兴趣数据
2. When 管理员打开统计页
3. Then 页面展示用户数、景点数、预约数和行程方案数
4. And 页面展示热门景点排行和兴趣分类分布
5. And 指标与同一测试数据集的直接统计结果一致
6. And 热门景点按“收藏数 + 2 × 未取消预约数”降序排列，同分时按基础热度降序排列

## 8. 非功能验收

### AC-NFR-001 性能

- 在团队记录的测试环境和种子数据下，重复执行景点列表、景点详情和个人记录查询，至少 95% 的服务端响应在 2 秒内完成。
- 对代表性的合法条件重复执行行程生成，每次在 5 秒内返回结果或明确失败信息。

### AC-NFR-002 兼容与响应式布局

- 在开发完成时最新版 Chrome 和 Edge 中完成景点搜索、行程生成、预约和管理员景点管理流程，无阻断性兼容问题。
- 在团队选定的常见手机宽度下，核心操作无不可达控件、文字严重遮挡或阻断操作的横向滚动。

### AC-NFR-003 安全

- 检查持久化数据，确认密码字段不是明文密码。
- 在不依赖前端页面的情况下直接请求受保护接口，确认未登录、角色错误和资源所有者错误均被服务端拒绝。
- 对搜索、评论及管理表单输入代表性的脚本、SQL 特殊字符和超长内容，系统不执行注入内容且按规则处理或拒绝。

### AC-NFR-004 可靠性与测试

- 模拟保存行程或创建预约过程中的服务端失败，确认没有用户可见的半完成主记录。
- 自动化测试至少覆盖：登录与角色权限、推荐核心规则、预约日期/人数规则、评价资格与评价唯一性。

### AC-NFR-005 分页与个人数据数量

- 用户创建超过单页容量的收藏、行程或预约记录后，所有记录仍可通过翻页访问。
- 管理员面对超过单页容量的预约或评价记录时，可以分页查看，筛选条件在翻页时保持有效。
- 系统不因达到人为设置的收藏、行程方案或预约总数上限而拒绝合法请求。

## 9. 验收通过规则

1. 所有 Must 场景通过；不存在导致核心流程无法继续的缺陷。
2. Should 场景按实际完成情况验收，未完成项必须记录为已知限制。
3. Could 场景不影响 MVP 是否通过。
4. 若实现行为与本文不一致，应先更新需求决策并获得小组确认，而不是仅修改测试以适配当前实现。
